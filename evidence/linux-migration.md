# Linux reproducibility migration — review record

This is an unpromoted development migration from repository commit
`7dde783068f137b1b6632292fe321957da06efb4`. It does not reissue an existing
publication or certify that Linux reproduces all historical Windows results.

## Contract and implementation

- `RUNTIME-linux.json` is the Linux development profile. `tools/verify.py` selects
  the Linux controller on Linux; the historical Windows controller remains intact.
- CPython 3.12.10 comes from a hash-pinned Astral standalone archive. Git 2.47.3
  comes from a hash-pinned Debian binary package. Both install under ignored local
  directories. The executable hashes are checked at verification time.
- The original 53-package hash lock is unchanged. Linux OpenBLAS shared-library
  bytes, single-thread Haswell execution, CPU restrictions, Matplotlib font bytes,
  Pandoc, Chromium revision/version and executable are verified explicitly.
- Microsoft PowerShell 7.5.4 is pinned for the workflow guard tests. Its archive
  digest agrees with the upstream release checksum file. Verification uses local
  cache/config/data directories and disables PowerShell telemetry for that process.
- Debian 13 and glibc 2.41 are checked. CI declares the Chromium and PowerShell
  shared-library prerequisites. The Debian image tag and system-package selection
  are not a complete immutable OS-image lock; no universal renderer identity is
  claimed across host-library updates.
- `RUNTIME.json`, the original frozen benchmark, its test source, immutable release
  metadata, original data, figures, manuscripts, and published Atlas bytes remain
  unchanged. Historical release workflows retain their Windows authority boundary.
- The Linux CI job has only `contents: read`. It invokes the complete Linux gate;
  it is expected to remain red while scientific equivalence is unresolved. It has
  not been run on GitHub. No workflow has been dispatched and no settings changed.

## Verification performed

The following commands were executed locally. Long-running output is retained in
ignored `tmp/` directories; those outputs are not release artifacts.

```sh
python3 -I -B tmp/linux-bootstrap-smoke/tools/bootstrap_linux.py
tmp/linux-bootstrap-smoke/.venv/bin/python -I -B \
  tmp/linux-bootstrap-smoke/tools/verify_linux.py --runtime-only
.venv/bin/python -I -B tools/verify.py --runtime-only
.venv/bin/python -I -B tools/verify.py
.venv/bin/python -I -B tools/verify.py --all --workers 4
.venv/bin/python -I -B -m ruff check .
.venv/bin/python -I -B -m mypy src
.venv/bin/python -I -B tools/release_integrity.py write-manifest
git diff --check
```

The bootstrap smoke test used a new directory containing copies of the bootstrap,
controller, and required configuration files. A fresh Python environment and
registry dependencies were installed, then runtime verification passed. After the
PowerShell addition, bootstrap and runtime verification passed there again.

The first committed Linux focused run passed 431 tests, with 17 PowerShell-dependent
skips and one explicitly deselected historical byte test. Installing the pinned
Linux PowerShell enabled all 18 preflight tests; those passed. The Linux-specific
negative controls also passed, including rejection of altered executable/archive
bytes, changed discrete results, nonfinite numbers, optimizer-value drift, and
nonrepeatable generated bytes. They verify that a failed replay records its failure
without overwriting historical inputs.

Repository admission, Ruff, mypy, citation validation, repository/external links,
Pages admission, retained PDF inspection and manifest checks passed. The Linux
controller also checks the committed inventory and Git archive against the manifest.

The deselected test is the frozen Windows benchmark byte assertion. Its source is
itself part of that experiment's frozen inputs and has not been edited. The Linux
replacement checks those same inputs, exact Linux result bytes, all original
scientific outcome assertions, and numerical equivalence to the historical results
at relative/absolute tolerance 1e-12. Its seven changed floating-point values have
maximum absolute difference 5.551115123125783e-17. No discrete result changed.

## Scientific and rendering differences

The broader core replay does **not** meet the same strict scientific comparison.
The initial isolated Linux replay changed 23 of 53 scientific artifact byte hashes;
30 matched. The two basic demonstration JSON summaries met the numerical comparison.
The nonlinear topology fits and ensemble did not.

For example, the chain conductance changes from
`[0.22887601612574368, 1.393862770271663]` to
`[0.22887602186647643, 1.3938627473481648]`. Its accepted optimizer starts change
from 8 to 6, and its selected start from 4 to 9. Those differences cannot be called
bitwise or diagnostic equivalence. The triangle's mean held-out RMSE changes from
`0.0002696852247203885` to `0.0002696852061158471`.

The headline ensemble outcomes agree: chain selection is 64/64, the triangle has
lower held-out error in 23/64 cases, and 29 shortcut fits hit the lower bound. Those
agreements are useful evidence, but are not a substitute for the failed full gate.
The migration keeps the strict gate; it does not enlarge tolerances after seeing
these results or replace the historical fits with the new ones.

The Atlas HTML and its accessibility report match historical bytes exactly. The
Linux PDF passes its structural/font checks but has 27 pages instead of 28, and
normalized extracted page text/order differs with line wrapping and mathematical
layout. Its bytes and inspection report therefore differ. It remains an unpromoted
Linux rendering; no publication identity is generated or replaced.

## Remaining acceptance boundary

Linux development checks and full historical reproduction are separate claims.
A reviewed scientific acceptance policy for the nonlinear optimizer outputs, and
a review of the changed PDF layout, are required before a Linux publication baseline
can be established. The full migration gate must remain failed until that work is
completed. No tolerance waiver, release promotion, remote write, or security change
is included in this branch.
